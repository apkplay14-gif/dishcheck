# Реклама: що вже зроблено і що лишилось

> Загальний план випуску (реклама + Google Play) — у [RELEASE.md](RELEASE.md).

Пам'ятка для повернення до теми. Стан на 1 вересня 2026.

> **Спершу прочитайте це.** Банер віддає ~$0.3–1.5 за 1000 показів. При кількох
> монтажниках це $1–3 на місяць, а поріг виплати AdMob — **$100**. Плюс для
> застосунків, яких немає в магазині, AdMob часто вмикає обмежену видачу, і
> реклама може взагалі не приходити. Тобто зараз усе це радше «щоб було».
> Реальний сенс зʼявиться тільки якщо застосунок піде в Google Play і його
> ставитимуть сотні людей.

## Що вже працює

- Банер унизу головного екрана — [ui/AdBanner.kt](app/src/main/java/ua/starlink/reader/ui/AdBanner.kt)
  - тільки на головному екрані; на сканері й у картці комплекту реклами немає навмисно
  - inline-формат, на всю ширину, не вище 60dp
  - якщо реклама не завантажилась (немає інтернету або AdMob не дав заповнення) — банер не займає жодного пікселя
- Збір згоди GDPR через Google UMP — [ads/AdsConsent.kt](app/src/main/java/ua/starlink/reader/ads/AdsConsent.kt)
  - спершу згода, і лише потім ініціалізація SDK реклами
  - в Україні користувач не бачить нічого: UMP визначає регіон і одразу дає дозвіл
  - у ЄС при першому запуску показується форма Google
  - пункт «Налаштування конфіденційності» зʼявляється в розділі «Додатково» сам, тільки там, де згода була потрібна
- Текст політики конфіденційності — [docs/index.html](docs/index.html), українською та англійською
- Бібліотеки: `play-services-ads 25.4.0`, `user-messaging-platform 4.0.0`

**Зараз стоять тестові ідентифікатори Google.** Показується заглушка «Test Ad»,
нічого не заробляється, на неї можна безпечно тиснути.

## Що лишилось зробити

### Крок 1. Вписати пошту в політику

У [docs/index.html](docs/index.html) у двох місцях стоїть `ВАШ_EMAIL`.
Не заповнив сам, бо сторінка публічна — вирішувати вам, який адрес там світити.

### Крок 2. Опублікувати політику на GitHub Pages

**Важливо:** GitHub Pages з приватного репозиторію працює лише на платному тарифі.
Тому не кладіть політику в репозиторій з кодом — зробіть окремий публічний.

```bash
mkdir ye-starlink-privacy && cd ye-starlink-privacy
cp "D:/CLODE/Starlink/docs/index.html" .
git init && git add . && git commit -m "Privacy policy"
```

На github.com: **New repository** → назва `ye-starlink-privacy` → **Public** → створити.

```bash
git remote add origin https://github.com/ВАШ_НІК/ye-starlink-privacy.git
git branch -M main && git push -u origin main
```

У репозиторії: **Settings → Pages → Source: Deploy from a branch → main / (root) → Save**.

Хвилини за дві сторінка буде доступна за адресою:

```
https://ВАШ_НІК.github.io/ye-starlink-privacy/
```

Перевірте, що вона реально відкривається з телефона — AdMob цей URL перевіряє.

### Крок 3. Завести AdMob і отримати ідентифікатори

1. [admob.google.com](https://admob.google.com) → створити акаунт
2. **Apps → Add app**
3. На питання «Is your app listed on a supported app store?» → **No**
   (застосунок роздається файлом APK, у магазині його немає)
4. Скопіювати **App ID** — виглядає як `ca-app-pub-0000000000000000~0000000000`
5. **Ad units → Add ad unit → Banner**, дати назву (наприклад `main-bottom`)
6. Скопіювати **Ad unit ID** — виглядає як `ca-app-pub-0000000000000000/0000000000`

Зверніть увагу на розділювач: у App ID це `~`, в Ad unit ID це `/`.

### Крок 4. Підставити ідентифікатори

Єдине місце — [app/build.gradle.kts](app/build.gradle.kts), рядки 23–24:

```kotlin
manifestPlaceholders["admobAppId"] = "ca-app-pub-ВАШ~APP_ID"
buildConfigField("String", "AD_UNIT_ID", "\"ca-app-pub-ВАШ/AD_UNIT_ID\"")
```

Більше ніде їх міняти не треба — далі вони самі розходяться в маніфест і в код.
Після зміни: `gradlew.bat assembleDebug`.

> **Ніколи не тисніть власну справжню рекламу.** За це блокують акаунт назавжди,
> і відновити його практично неможливо. Для будь-якої перевірки повертайте тестові
> ідентифікатори — вони записані нижче.

### Крок 5. Створити повідомлення GDPR

Без цього форма згоди в ЄС просто не зʼявиться, хоч код і готовий.

**AdMob → Privacy & messaging → GDPR → Create message**:
- вибрати застосунок
- вставити URL політики з кроку 2
- опублікувати

Там же, у **Privacy & messaging**, окремо вкажіть **Privacy policy URL** для самого застосунку.

## Як перевірити форму згоди з України

Просто так ви її не побачите — UMP покаже форму лише в ЄС.

1. Запустіть застосунок з підключеним `adb logcat`
2. Знайдіть у логах рядок виду:
   `Use new ConsentDebugSettings.Builder().addTestDeviceHashedId("ABC123...")`
3. Вставте цей хеш у [app/build.gradle.kts](app/build.gradle.kts), рядок 32:
   ```kotlin
   buildConfigField("String", "CONSENT_TEST_DEVICE_ID", "\"ABC123...\"")
   ```
4. Перезберіть — застосунок вважатиме себе в ЄС і покаже форму

Працює **тільки в debug-збірці** — у release цей блок не виконується.

## Як вимкнути рекламу повністю

[app/build.gradle.kts](app/build.gradle.kts), рядок 27:

```kotlin
buildConfigField("boolean", "SHOW_ADS", "false")
```

Банер зникає, SDK не ініціалізується, форма згоди не показується.
Бібліотеки лишаться в APK — щоб прибрати й їх, видаліть два рядки залежностей
(85–86) і файли `ui/AdBanner.kt`, `ads/AdsConsent.kt`, а також виклик
`AdsConsent.gather(this)` у `MainActivity` і `bottomBar = { AdBanner() }` та
`PrivacyOptionsEntry()` у `ui/Screens.kt`.

## Що ще знадобиться, якщо підете в Google Play

- **Data safety** — декларація в Play Console про те, які дані збираються
  (рекламний ID, приблизне місцезнаходження — все через AdMob)
- **app-ads.txt** — файл на вашому домені, підвищує заповнення реклами
- Питання назви: «Starlink» — чужа торгова марка. Для Play краще власна назва,
  а Starlink згадувати лише в підзаголовку й описі
